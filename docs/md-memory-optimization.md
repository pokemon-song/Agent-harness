# 记忆 Agent 优化与验证

版本 `0.5.0.dev3`，分支 `feature/async-md-memory-agent`。本次针对 [上一轮复杂实验](md-complex-memory-test.md) 中的公告排队、反复写入错误、正文信息退化和高上下文成本进行优化。

## 处理与决策分工

模型继续决定记什么、如何命名文档、如何解释证据和修订正文。Harness 负责事件调度、版本一致性、工具参数与执行门控；没有程序提取订单答案、拼接正确回执或代写语义记忆。

- **关键公告优先**：每次选批优先选择待处理关键事件，按来源序号排列。以旧事件水位 18、新公告 35 为例，可先确认 35，同时保持连续水位 18，19–34 仍然待处理。`acknowledged_event_seqs` 保存已单独确认的序号，`pending_event_count` 给出真实待处理数；旧反馈完成后才推进连续水位。
- **运行中重新调度**：普通反馈请求期间到来关键事件，在请求返回边界放弃旧回复并重新选批；如果该普通请求失败，同样调度新公告，不因消费了通知而永久等待。失败请求保留原日志和未知用量；关键事件处理后，旧反馈可按新版本在新批次重新处理，所有请求仍计入原有预算。网络请求本身仍不能实时抢占。
- **更新后刷新规划**：关键事件尚未处理时继续禁止动作；关键公告已发布时，旧规划仍需刷新，并读取新增或改变的文档。普通、无关文档更新不会使所有计划失效。空语义提交要求刷新，但不制造可供读取的文档。
- **局部修改**：新增 `patch_memory`，模型提供旧句和新句，只有旧句唯一精确匹配才替换；未修改正文按字节保留。修改既有文档前必须先 `memory_read`。补丁合并原证据与新证据，超过 16 条时要求模型明确协调全文与证据，不静默删引用。
- **可纠正的工具错误**：公开允许目录、240 字符路径、6,000 字符正文、16,384 字节工具参数等约束。错误包含字段和实际／允许长度，不回显任意异常或被拒正文。模型仍需遵守一轮一个工具。
- **区分证据性质**：提示词明确调度公告本身可证明任务授权，不需要动作反馈再证明该指令成立；物理位置、通过障碍和执行成功需要测量证据。订单身份、编码、修订号要求逐字保存，当前任务与导航历史应分文档维护。

## 上下文缩减

原始事件账本和图片完整保留。对已知普通 `robot_feedback`，模型默认只接收请求动作、完整结果、测得的后状态与跟踪几何；省略重复的前观测及前后相同的任务／配置。变化的任务或标定、`tracked_points`、未知新观测字段继续提供。关键公告逐字提供，不做语义摘要。

投影附带省略字段说明及原事件 ID，模型可用 `inspect_event` 查看本批或已确认历史的完整事件。读取 MD 时只提供一次正文及结构化元数据，不再重复 `content` 和 `body`；短期工具历史不重复整批事件。以上是字段投影和去重，不等于 token 计费量或模型质量改善。

## 保留的限制

优化后的全量回归 **1,084 项通过，29.73 秒**，包含队列、竞争写入、关键事件通知、文档更新、错误反馈、旧库兼容和导航门控。初次全量运行暴露了一项旧测试将普通知识更新标为 critical 的假设；已明确区分普通更新可继续、关键更新需刷新，两种行为分别验证。

局部补丁保证未改文字不被机械重写，不能证明模型选中了正确的修改范围；模型仍可选择全文替换。引用有效也不等于句子被证据支持。未知参数、过长正文、传输失败和超时仍会保留为失败。持续出现关键事件可能推迟普通反馈；总调用和墙钟预算仍有上限。当前实现不提供现实机器人实时抢占保障。

旧目录无数据库迁移，旧快照和幂等收据可继续读取，打开不会重写历史。新增日志和报告同时展示连续水位、稀疏确认及待处理数量。旧版复杂实验及其成绩保持原始记录；本次回归和短测另行归档，不冒充完整六阶段重测。
