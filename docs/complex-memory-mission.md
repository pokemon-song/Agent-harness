# 多区分流与三班修订记忆任务

版本0.4.0把原先“记住完整订单、重启后复述”扩为三班信息组合和一次真正改变导航路线的订单修订。机器人仍为Go2/MuJoCo，主模型自主选择动作与所有记忆操作，没有新增自动规划、自动检索或自动总结程序。新任务独立于原v2/v3榜单。

## 实际场景

最终地图约8.8×6.2米，分为出发绕障区、汇合区、收货区。出发区柜体阻挡直行；横向隔墙有蓝门和黄门，两扇门物理上始终可通行。模型必须从保存的有效订单决定哪条通道获准通行。越过所选通道后，绕开第二个柜体并重新对准绿色门；从绿门通过后继续至少0.8米，再到A/B/C中的正确收货标牌停稳。

蓝／黄门净宽均1.4米，绿色门净宽1.6米。公开规则要求穿门时base相对开口中心横偏不超过0.55米，并全程避免碰撞。评分独立检查真实轨迹的门面穿越方向、开口范围和先后次序；走错门后再补走正确门不能清除错误。最终场景及两条通路不随正确订单变化，模型不能从哪扇门被堵住猜答案。

前三班是分别初始化的学习区域：第一班仍做绕柜、穿门、接近B的复合巡检；第二班绕过两组交错箱体；第三班绕过维护设备。各班B只是当前巡检终点，不是最终订单答案。每次交班会关闭模型进程并重置机器人，属于跨回合长期记忆测试，不是连续不重置的大地图漫游。

## 三班知识依赖

| 班次 | 本班提供的信息 | 需要保留的关系 |
| --- | --- | --- |
| `dispatch` | 订单ID、R1目的地区域别名、R1许可蓝／黄通道、回执码前3位 | 早期片段属于哪个订单；别名还不能直接对应标牌 |
| `fragments` | 同一订单回执码后3位、三个区域别名到A/B/C的随机映射、另一订单的干扰信息 | 合并两段码，解析正确订单的别名，避免串单 |
| `revision` | R2改变目的地区域别名及许可通道，随后展示明确标记ARCHIVED/R1的旧公告 | 使用有效的高版本，保留未修改的码和映射，不被后出现的旧记录覆盖 |
| 最终交付 | 只给订单ID、通用流程与验收规则 | 从记忆自行组合最新订单，选路、导航、提交回执并完成 |

第三班不再出现码的任一片段或区域映射。前后半段为独立随机的三位字符串，保留前导零；代码拼接不是相加。别名映射为随机双射，订单号与答案独立，新旧目标别名必然不同，新旧许可通道也必然不同。

每班公告在本班任务文字中持续可见，不是只闪现一次。模型通过已有公开机器人回合取得证据引用，自主决定保存、追加或修订。程序不补写遗漏字段，不要求固定工具顺序，也不要求必须使用`memory_revise`；正确保留版本和最终使用新信息才是验收对象。

## 三个一致条件的最终回合

| 条件 | 只读记忆来源 | 作用 |
| --- | --- | --- |
| `full` | 模型在第三班结束后的真实SQLite副本 | 检验完整信息及修订是否可用 |
| `stale` | 模型在第二班结束后的真实SQLite副本 | 保留前两班全部实际记忆，缺少第三班正式修订 |
| `empty` | 同结构、同机器人作用域的空库 | 检验没有交班信息时的表现 |

三个条件使用同一场景、起点、图像、任务、模型、工具和预算，分别启动全新进程，清空历史、跟踪点和临时笔记。副本通过SQLite备份产生，不手工删改记忆。若模型前两班未保存完整码，stale就不能被描述为“已知完整旧订单”；报告按实际读取与提交证据说明。

最终工具`submit_mission(order_id, dispatch_revision, destination, receipt_code, route)`只接受首次格式有效的答案，在线回包仅确认收件。任务结束后才核验订单、版本、别名解析后的目的地、两段码、声明通道与实走通道。路线验收使用正确合同，不使用模型自己声明的通道来放宽规则。

## 成绩与失效条件

完整任务要求三个学习班次和full交付全部严格成功。每回合单独报告墙钟时间、仿真时间、真实路径长度、API调用与token、碰撞／跌倒、最终停止及工具错误。最终交付分开报告物理到达、正确版本、目的地、前／后半码、声明通道、实际门序及绿门余量；不会将碰撞失败统称为记忆失败。

`demonstrated_memory_dependency`还要求full实际读取非空记忆、空库主动中止、三个对照条件有效并通过一致性审计。`demonstrated_update_dependency`要求full确实读取记忆且full/stale快照不同；stale正常finish并提交了完整正确码及完整旧订单值，才将其失败作为采用过期调度的案例证据。单纯碰撞、预算超限、缺码、基础设施或清理异常都不能支持这项结论。以上是单次案例标记，不是统计显著性证明。

学习回合若物理失败但已存下非空记忆且无基础设施错误，后续允许继续诊断，完整任务仍失败。若没有可交班记忆，则保留失败并停止，不由程序补答案。所有失败原样保存，不自动重试或重抽订单。

## 运行与预算

| 回合 | 最大模型调用 | 最大墙钟 | 最大仿真 |
| --- | ---: | ---: | ---: |
| dispatch | 40 | 900秒 | 150秒 |
| fragments | 30 | 900秒 | 150秒 |
| revision | 30 | 900秒 | 150秒 |
| full／stale／empty，每组 | 60 | 1200秒 | 240秒 |

一次实验最多280次API调用。三个最终条件的预算完全相同，不能单独给空库或旧库缩额。阶段顺序固定，服务时延和模型采样波动仍是局限；正式比较还需更多预注册样本及条件顺序平衡。

```bash
# 帮助，不读密钥、不请求模型
.venv/bin/python scripts/run_complex_memory_mission.py --help

# 会调用真实DeepSeek，默认保存每控制步的录像状态
MUJOCO_GL=egl .venv/bin/python scripts/run_complex_memory_mission.py

# 回复较长时，新建独立实验并显式冻结更大的回复预算
MUJOCO_GL=egl .venv/bin/python scripts/run_complex_memory_mission.py \
  --max-output-tokens 16384 --api-timeout 180

# 在实验结束后按仿真时间生成连续第三视角视频
MUJOCO_GL=egl .venv/bin/python scripts/render_complex_memory_video.py runs/<实验目录>

# 生成报告和默认播放连续运动版的页面
.venv/bin/python scripts/report_complex_memory_mission.py runs/<实验目录>
```

原始状态采样包含每段任务的动作与最终停车，初始约1秒站稳不在评测内。录像默认1秒视频对应1秒仿真，避免无实时限速计算造成的位置突跳。各段之间用RESET卡说明换进程和换场；模型等待时的暂停被移除，真实等待时长另列在报告。需要实际耗时版时，显式使用`--include-wall-time`；它可能将运动压成少量画面，不应作为观看步态的主视频。

每次实验冻结代码、所有脚本、提示词、私有合同及Git提交，创建新目录，保护旧结果。`contract.private.json`只用于独立验收及公告分配，最终模型看不到该文件。API密钥仍从本地既有配置读取，日志不保存密钥或私有推理。

## 无模型物理验证

实现阶段已用真实Go2控制器检查蓝／黄两条路线及两个新增学习区：四条验证均零碰撞、零跌倒并到达目标。两条最终路线分别为24个运动动作、约80.52／79.50秒仿真、9.317／9.277米；两个学习区分别17／15动作、57.96／51.20秒仿真。验证用私有坐标导航，仅说明场景可达，**不计为大模型成功**。

## 首次模型试验的协议中断

`31bd20f`上的首轮`20261110-093431-complex-memory-24ea05`使用每次8192输出token、90秒API超时。模型完成4次原地视觉选点，第5次回复被截断而触发`MODEL_PROTOCOL_ERROR`，102.24秒后终止；未执行导航、未保存长期记忆，其余5阶段按规则未运行。不能将其解释为复杂场景导航或记忆能力失败。5次请求中仅4次有完整用量，已知41680 token，最后一次的缺失用量不按零计费。

该失败原样保留。后续增额实验必须新建目录，显式设置16384输出token、180秒API超时；仍保持原每回合总调用数、墙钟和仿真预算，三种交付条件设置完全一致，不在已冻结的运行中改限额。这是改变配置后的新实验，不覆盖或排除首轮记录。

## 增额后的真实测试

第二组`20261110-093854-complex-memory-d1d607`冻结在`3c683a5`，使用16384输出token和180秒单次请求超时，生成独立新合同。第一班20个工具回复正常，第21次请求触发`MODEL_TIMEOUT`。回合墙钟515.87秒、仿真30.22秒，机器人已经通过柜后余量，尚未穿过绿门或到达B，0碰撞、0跌倒，最终安全停止。

两次实验均未调用持久记忆保存，实际长期记忆条目为空，因此剩余fragments、revision、full、stale、empty五阶段按预定规则未运行。三项成功标志保持false；这表示完整实验未通过，不构成模型无法处理修订或多区地图的证据，因为这些阶段尚未被模型执行。两个独立合同、采样行为及请求配置均有变化，不能把第二次行走更远归因于提高输出预算。

第二组已记录21次请求中的20个完整用量，共600556 token；超时请求用量未知。两次合计26次请求尝试、24条完整回复、已知642236 token。未知用量不能按零费用处理。软件实现、874项回归测试与四条真实控制器可达性检查已经完成，但新的六回合大模型实验**尚未跑通**。
