# A/B 遮挡返回：碰撞记录扣分后继续，r4

日期：2026-11-23。实验：`fresh-subgoal-retain-24x18-s0-1024-r4`。

结果：有记忆组完成 A→B，独立判定通过，得分 95；无额外记忆组未通过 A，模型主动放弃，得分 0。两组发生接触后均继续执行，碰撞没有直接结束任务。

重要限制：有记忆组虽然启用了记忆模块并记录了经历，但本轮没有调用任何 `memory_query`，记忆读者请求也为 0。因此本轮成功不能作为记忆 Agent 检索有效的证据；规划器可使用的是本回合完整对话、图像及工具反馈。

## 本轮条件

- 两组均从起点独立重置，实时运行，不复用旧轨迹、旧对话或旧记忆。
- 使用持续子目标架构，`--handoff-context retain` 保留所有公开规划对话、图像与动作反馈。有记忆组还保留已有文档、答复卡及缓存。
- 场地 24×18 米，seed=0，deepseek-flash，thinking 关闭。
- 每阶段最多 1024 次 API 请求、230 个原生动作、940 秒仿真时间、2234 秒墙钟时间。单次请求输出上限 8192 token、超时 90 秒。
- 与 r3 相比，碰撞改为 `record_and_penalize`，提示词同步说明碰撞后继续。运行中没有再次修改代码。
- A 通过得 50 分，B 在整轮完成时再得 50 分；每个独立碰撞事件扣 5 分，最低 0 分。是否通过与扣分后的总分独立。
- 距离、朝向、停稳、A→B 顺序及 finish 的独立判定保持原标准。

## 对照结果

| 指标 | 无额外记忆＋完整上下文 | 有记忆＋完整上下文 |

| B 通过 | 未进入 | 是 |

原生动作预算按阶段计算，因此有记忆组全程 240 个动作没有超限：A 使用 149/230，B 使用 91/230。累计输入包含反复发送的历史，不能理解为去重后的记忆长度。

## 有记忆组的完整流程

1. 去程自主扫描和绕柜搜索，第 44 次规划输入首次看到 A。
2. 第 60 次规划完成 A 停靠，独立测得中心距离 1.1449 米、朝向误差 0.0944 rad，确认停止。
3. 仿真时间 406.80 秒切换到 B。首次返程请求保留全部 60 轮去程历史、182 条消息和 60 个图像块；当前目标切换为 B。
4. 第 9 次返程规划输入重新看到 B，随后多次调整接近路线和朝向。
5. 第 33 次返程规划完成 stop、复测和 finish。最终距 B 中心 1.1174 米，朝向误差 0.0511 rad，已停稳，独立评分通过。

B 阶段若干次 `execution_slice_complete` 是正常的六动作分段返回。模型有时将其当作停靠受阻而重建目标，增加了路线调整；后续继续执行后完成了任务。本轮没有跟踪点容量错误。

去程的一次 B 接触记录在案，后续任务继续完成。最终 `collision=true` 与 `success=true` 同时成立，按新标准扣 5 分后得到 95 分。

## 无额外记忆组的流程

第 31、32 次规划输入看到 A，但随后选择的接近方向偏离目标，走回柜体附近并丢失 A。后续多次扫描、换位，第 49 次规划主动调用 abort。当时还剩 129 个原生动作和 975 次请求预算，未耗尽限制。

两次柜体接触均已记录。第二次接触后仍继续运行约 60 秒，直至模型主动放弃。它没有通过 A，未进入返程；不是碰撞终止。

## 结论边界

本轮验证了“发生碰撞仍可继续，达成目标仍可通过”的实际运行行为。有记忆组完成了任务，但没有读取外部记忆，因此不能把这次两组差异直接归因于记忆 Agent。每组仍只有一个样本，模型搜索路线和恢复决策存在明显波动。
